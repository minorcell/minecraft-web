# 架构改进与长期规划（精简版）

## 愿景

在不大幅增加复杂度的前提下，让当前 3D 体素项目具备更好的解耦、可扩展性和可维护性，为未来插件化留出空间。

## 现状与目标

```
现状
├─ World 聚合根：生成 + worker 协调 + 渲染协调，职责过重
├─ Terrain/Village：生成逻辑集中且清晰
├─ VoxelBuilder：渲染高效，但与 World 强耦合
└─ Player：输入/运动/碰撞

目标（轻量扩展）
├─ 事件总线 + 钩子：生成/渲染/拾取等通过事件解耦
├─ 配置化注册表：建筑/装饰/生物群系/材质可配置扩展
├─ 协调角色拆分：WorkerCoordinator、RenderCoordinator 从 World 拆出
└─ 扩展点：通过配置/事件添加新内容；真正的插件管理器暂缓
```

## 第一阶段

- **事件总线 + 钩子**：引入轻量 EventEmitter；为 chunk 加载/卸载完成、worker 生成完成、装饰生成完成、掉落拾取等发事件，订阅侧更新渲染或 UI。
- **配置化注册表**：集中建筑/装饰/生物群系/材质配置，World/Village/Decoration 读取配置而非硬编码，方便添加新内容。
- **职责拆分（无 IoC）**：将 World 的 worker 协调、渲染协调拆成小类，通过构造注入；保留简单依赖，不上容器。
- **预留钩子**：在生成/渲染流程中加入 hook 列表，先让自有功能通过 hook 走通，再开放给外部。

## 后续演进（有需求再做）

- 如果出现第三方扩展/动态加载需求，再评估插件管理器和 IoC 容器。
- 性能侧可逐步引入：空间分割、视锥裁剪、纹理图集、生成管线并行化等。

## 预期收益

- 解耦：组件通过事件沟通，减少 World 的直接依赖。
- 可扩展：新增建筑/装饰/材质只改配置/注册表，不动核心代码。
- 可维护：职责拆分后，生成与渲染协调更清晰，调试成本降低。
